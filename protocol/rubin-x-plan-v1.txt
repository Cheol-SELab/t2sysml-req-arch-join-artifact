Rubin-X controlled cross-identifier experiment — pre-specified plan v1 (ACCESS-050), written 2026-10-31 BEFORE any
pipeline call on Rubin-X material.

Purpose: Open PCA is the only natural document whose allocation lists cite requirements under identifiers different
from the definitions (a consistent chapter shift); a third-document screening found no further public document with
that property and an independent trace artifact (ACCESS-049). Rubin-X isolates the join step under a controlled
intervention: the same requirement carries unrelated identifiers in the two documents.

Material: LSE-61 v6.2 + LDM-148 v8.1 (same sources and GT rules as Rubin, GT v1.1 text correction). LSE-61 keeps the
Rubin remapping (DMS-REQ -> DMSR, seed 20261031); LDM-148 receives an independent permutation (seed 20261101).
0 requirements keep the same number in both documents; 5 design-side numbers coincide with the definition-side number
of a different requirement (exact-identifier traps). Built by scripts/build_gt_rubin.py <...> v1.1 split.
Input data/frozen/rubin/rubin-x-remapped.txt; GT data/frozen/rubin/rubin-x-gt-v1.json (1,187 claims, 1,152 supported,
35 not-established; claim i identical to rubin-gt-v1.1 claim i except cited_id = LDM-148-side identifier).
The join is possible only through title/wording: supported claims have equal (normalized) titles in 15.2 and LSE-61.
This is a constructed variant and is reported as such ("controlled cross-identifier variant"), never as a third
natural document.

Arms (frozen code, unchanged prompts, chunk 1,500 tokens): B0, B1, B2, M (pipeline.py v1); M2R (pipeline_v2.py v2.1,
post-hoc method, secondary). Models gpt-6.1-sol and claude-opus-5-5, 3 runs each. Chunks of the LSE-61 part are
byte-identical to Rubin and are served from the response cache of the same (model, run); this is a paired design,
not a deviation. No memory arm (identifiers are remapped as in Rubin; the Rubin memory arm applies).

Hypotheses (per model; paired component bootstrap, 10,000 resamples, seed 20261031; full recall; scorer unchanged):
  X1  M v1 - B1 > 0 (lower 95% bound > 0)      [primary: the join step recovers allocations an exact-id join cannot]
  X2  M v1 - B2 > 0 (lower 95% bound > 0)
  X3  descriptive join cost: M v1 on Rubin-X minus M v1 on Rubin (GT v1.1), paired by claim, mean and 95% CI
  X4  descriptive: wrong merges and not-established links per run, M v1 vs B1 (B1 can merge only on the 5 traps)
Secondary: M2R vs M v1, B0 reference, precision decomposition (scripts/precision_rubin.py), cost.
Failure handling: a crashed run is reported; primary analysis over completed runs, sensitivity with the crashed run
counted as recall 0 (as in ACCESS-045).
No change to code, prompts or ground truth after the first call; deviations are logged.
