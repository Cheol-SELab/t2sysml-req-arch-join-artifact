근거 결합 판정 규약 v1 — 2026-10-31 동결 (ACCESS-015)

v0와의 차이: 독립 인간 검토자를 없애고, GT를 공식 모델·추적표와 문서의 결정적 정렬로 구성한다(ACCESS-005). 아래 규칙은 scripts/align_fprime.py, scripts/align_openpca.py v0가 구현한 그대로이며, 변경은 v2로 올리고 decisions/log.csv에 수정 사유를 남긴다.

1. 판정 단위
하나의 model claim은 요소/관계 유형, 참여 대상, 조건, 제약, 적용 범위를 포함한다. 표현 문법이 달라도 같은 명제인지 확인할 수 있어야 한다.
명제 유형: A 요구사항–설계 할당, B 조건·수량·시간 제약, C 계층·동일성, D 인터페이스.

2. 판정 값
supported / contradicted / not_established / not_modelable.
GT에 들어가는 명제는 supported뿐이다. not_established는 삭제하지 않고 이유와 함께 보존한다. LLM 판단은 어떤 열에도 GT로 들어가지 않는다.

3. 양방향 정렬 규칙 (GT 구성)
R1 모델→문서: 모델 요소·관계가 문서의 문장·표·각주에 명시 식별자(요구사항 ID, 포트 이름, 인스턴스 이름, 타입 이름)로 정확히 해소되어야 한다. 식별자 비교 전에 허용되는 정규화는 (a) 네임스페이스 표기 통일(`Svc::X` = `Svc.X`), (b) 모델 파일의 `module M { }` 안 비한정 이름에 `M.` 보정, (c) `import <Interface>`로 들여온 선언의 전개, (d) 표 셀의 `a / b` 병기 분리, (e) PDF 텍스트 변환에서 합쳐진 줄을 ID 토큰 경계로 재분할. 의미 유사성·부분 문자열·대소문자 차이 무시는 허용하지 않는다.
R2 문서→모델: 근거 위치(파일:행 또는 쪽·절·각주 번호)와 결합 필요성(단일 구간 충분 / 여러 문맥 결합 필요)을 기록한다. 두 근거 사이 토큰 거리는 기술하되 결합 필요성의 판정 근거로 쓰지 않는다.
R3 R1·R2를 모두 통과해야 supported. 하나만 통과하면 not_established.
R4 식별자 이동 규칙(Open PCA): 할당 목록·모델의 ID가 본문에 없을 때, 장 번호 +1 이동 후 ID가 일치하고 **제목 문자열도 일치**하는 경우에만 같은 요구사항으로 해소한다. ID만 일치하거나 제목만 일치하면 not_established. 이동의 원인 추정은 GT에 쓰지 않는다.
R5 문서–모델 불일치(drift) 분리: 이름이 다르나 타입·방향이 같은 포트(F Prime `Wdog`/`WdogStroke`, `Svc::Fatal`/`Svc.FatalEvent`)는 타입·방향 명제를 supported, 이름 동일성 명제를 not_established로 **분리 기록**한다. 삭제된 요구사항을 가리키는 할당(Open PCA R5.5.0(8))은 not_established.
R6 추적표·할당 목록·포트 표는 GT 원천이다. "산문 전용" 입력 조건에서는 이를 입력에서 제외하고, 표가 유일한 근거인 요구사항은 그 조건의 평가에서 제외한다. "표 포함" 조건은 별도 실험군이다.

4. 허용 및 금지 (v0 유지)
- 명시된 할당은 할당의 근거이다. 실제 성능 검증이나 충족 입증으로 확대하지 않는다.
- 요구사항과 기능 설명이 비슷하다는 이유만으로 만족/할당 관계를 확정하지 않는다.
- 번호/ID/이름이 같아도 버전, 대상 인스턴스, 범위가 다르면 분리한다.
- 시간, 수량, 단위, 조건문, 선택지, 의무 수준을 보존한다.
- 저장소/데이터 객체를 송신 소프트웨어로 바꾸지 않는다.
- 직접 전달, 매개 생산·사용, 할당, 추적을 구분한다.
- 문서에 연결 근거가 없으면 미확정으로 남긴다. 원문을 AI가 보완하여 GT로 만들지 않는다.

5. 입장 조건 — 모델 암기 검사 (ACCESS-007/011)
각 후보 프로젝트에 대해 문서를 주지 않고 기권을 금지한 프롬프트로 공식 산출물(포트 목록, 인스턴스 목록, 할당 목록 등)을 재현시킨다. 평가 대상 모델 전부에 대해 실행한다.
판정: 어느 한 모델이 한 프로브에서 공식 항목의 50% 이상을 정확히 재현하면 그 프로젝트는 **1차 시험 자료가 될 수 없고** 개발·파일럿 자료로만 쓴다. 패턴 열거로 맞출 수 있는 항목(연번 ID)은 재현으로 세지 않는다.
2026-10-31 결과: F Prime 불합격(7/8, 4/4, 8/8) → 개발·파일럿. Open PCA 합격(0/5, 0/31) → 1차 시험. Subset-026 합격(원문 재현 없음) → 2차 후보.

6. 저자 표본 점검
정렬 스크립트가 not_established로 낸 항목 전부와 supported의 10% 이상(무작위)을 저자가 원문으로 점검하고 data/reviews/에 기록한다. 점검은 GT를 바꾸지 않으며, 규칙 변경이 필요하면 규약 버전을 올린다.

7. 기록
정렬 스크립트 버전, 입력 커밋·SHA256, 출력 CSV, 점검 기록을 함께 보존한다. 원본 정렬 결과는 덮어쓰지 않고 재정렬은 새 디렉터리에 둔다.
