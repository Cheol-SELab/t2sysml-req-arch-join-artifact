근거 결합 판정 규약 v0 — 파일럿용, 아직 동결하지 않음

판정 단위
하나의 model claim은 요소/관계 유형, 참여 대상, 조건, 제약, 적용 범위를 포함한다. 표현 문법이 달라도 같은 명제인지 확인할 수 있어야 한다.

독립 판정 항목
1. 원문으로 지지되는가: supported / contradicted / not_established / not_modelable.
2. 같은 대상을 가리키는가: 명시 ID/별칭/참조, 문맥상 동일성, 미확정, 모순을 구분.
3. 조건·수량·시간·버전·계층 범위가 보존되는가.
4. 근거 집합: 문서 ID, 버전, 절/문장 위치, 각 근거의 역할.
5. 결합 필요성: 단일 구간 충분 / 여러 문맥의 결합 필요 / 미확정.
6. 짧은 대체 근거: 요약, 표, 재진술, 그림의 존재와 위치.
7. 허용 모델 표현과 확신도, 추가 가정.

허용 및 금지
- 명시된 할당은 할당의 근거이다. 실제 성능 검증이나 충족 입증으로 확대하지 않는다.
- 요구사항과 기능 설명이 비슷하다는 이유만으로 만족/할당 관계를 확정하지 않는다.
- 번호/ID/이름이 같아도 버전, 대상 인스턴스, 범위가 다르면 분리한다.
- 시간, 수량, 단위, 조건문, 선택지, 의무 수준을 보존한다.
- 저장소/데이터 객체를 송신 소프트웨어로 바꾸지 않는다.
- 직접 전달, 매개 생산·사용, 할당, 추적을 구분한다.
- 문서에 연결 근거가 없으면 미확정으로 남긴다. 원문을 AI가 보완하여 GT로 만들지 않는다.

입력 범위
텍스트 전용과 그림 포함을 사전에 정한다. 그림에 충분한 근거가 있다면 이를 숨겨 전체 문서 장거리 문제라고 주장하지 않는다.
단일 문서와 자연 다중 문서 묶음을 분리한다. 별개 자료를 인위적으로 합치지 않는다.
거리 수치는 선택한 근거 외곽인지, 최소 충분 구간인지 구분한다. 토큰 수만으로 결합 필요성을 판정하지 않는다.

판정 운영 (2026-10-30 개정)
독립 인간 검토자를 두지 않는다. 위 판정 항목 1~7은 공식 모델·추적표와 문서의 결정적 정렬 스크립트가 채우고, 저자가 표본을 점검한다.
정렬 스크립트 버전, 입력 해시, 점검 표본과 결과를 data/reviews/에 기록한다. 원본 정렬 결과는 덮어쓰지 않고 재정렬은 새 파일로 남긴다.
LLM 판단은 GT 열에 들어가지 않는다. 모델 암기 검사 결과를 프로젝트별로 기록한다.
이 규약은 실제 자료에서 파일럿으로 점검한 뒤 확정한다.
